# InsureTech — переход на Event-Driven архитектуру

## 1. Проблемы и риски текущей архитектуры

### 1.1. ins-product-aggregator — узкое место

- Делает синхронные запросы ко всем страховым компаниям.
- Добавление ещё 5 компаний увеличит задержки и вероятность ошибок.
- Ошибки внешних API полностью блокируют ответ агрегатора.

### 1.2. Локальные копии данных тарифов

- core-app обновляет кэш раз в 15 минут.
- ins-comp-settlement — раз в сутки (ночью).
- Данные становятся устаревшими, возможны расхождения.

### 1.3. Ночные батчи settlement

- settlement раз в сутки вызывает core-app за всеми оформленными полисами.
- При большой базе данных этот запрос становится тяжёлым.
- Проблемы в core-app в это время блокируют расчёты.

### 1.4. Недостаток событийной модели

- Нет push-уведомлений «обновился тариф», «оформлена страховка».
- Сервисы вынуждены poll-ить данные по расписанию.

### 1.5. Отсутствие Transactional Outbox

- Есть риск расхождения между локальными БД и уведомлениями внешних сервисов.
- Возможны ситуации: «записали в БД, но событие не отправлено».

---

## 2. Цели перехода на Event-Driven архитектуру

1. Уменьшить связность между сервисами (снять жёсткие REST-зависимости).
2. Обеспечить актуальные данные о продуктах и тарифах в реальном времени.
3. Упростить и ускорить расчёты ins-comp-settlement.
4. Обеспечить надёжную доставку событий (Transactional Outbox).
5. Подготовиться к росту до 10+ страховых компаний без деградации.


## 3. Предлагаемая архитектура (Event-Driven)

Ключевая идея — ввести **Event Streaming Platform** (Kafka / RabbitMQ)  
и перевести межсервисные взаимодействия на модель публикации/подписки.

### 3.1. Добавление Event Streaming Platform

Новый контейнер:

- **Event Streaming Platform**  
  (Kafka / RabbitMQ )

Основные топики:

- `product-tariffs` (обновления тарифов)
- `policies` (оформление/изменение/отмена полисов)

### 3.2. ins-product-aggregator → публикует события ProductTariffUpdated

- Продолжает интеграцию с 10 страховыми компаниями (REST/SOAP).
- Но больше не отдаёт данные синхронно по запросу других сервисов.
- Вместо этого публикует события `ProductTariffUpdated`.

### 3.3. core-app и ins-comp-settlement → подписчики тарифов

**core-app**

- Перестаёт делать REST к aggregator.
- Подписывается на `product-tariffs`.
- Обновляет кэш тарифов автоматически.

**ins-comp-settlement**

- Получает тарифы в реальном времени.
- Ночной процесс не зависит от aggregator.

### 3.4. core-app публикует события по полисам

При оформлении полиса core-app:

1. Записывает данные в свою БД.
2. Пишет событие (PolicyIssued / PolicyUpdated) в Transactional Outbox.
3. Outbox-воркер публикует событие в топик `policies`.

### 3.5. ins-comp-settlement → подписчик событий PolicyIssued

ins-comp-settlement:

- подписывается на топик `policies`;
- получает события сразу в момент оформления;
- сохраняет данные в свою БД;
- формирует реестры без зависимости от nightly REST к core-app.

Результат:

- больше нет тяжёлого запроса «дай все полисы за сутки»;
- settlement получает данные постепенно, без пиковых нагрузок.

---

## 4. Использование Transactional Outbox

### Зачем нужен

Чтобы избежать проблемы:

- данные записаны в БД, но событие не отправлено.

Transactional Outbox обеспечивает:

- атомарность операций (БД-запись + запись события в outbox);
- гарантированную доставку событий в брокер;
- защиту от потерь/дублирования.

### Где используется

- В **core-app** — для событий по полисам.
- В **ins-product-aggregator** — для событий обновления тарифов.

## 5. Изменения по сравнению с исходной диаграммой

1. Добавлен контейнер **Event Streaming Platform**.
2. Удалены периодические REST-вызовы:
   - core-app → aggregator (15 минут),
   - settlement → aggregator (сутки),
   - settlement → core-app (сутки).
3. Добавлены события:
   - `ProductTariffUpdated`,
   - `PolicyIssued`.
4. Добавлены **Transactional Outbox** внутри core-app и aggregator.
5. Все синхронные зависимости внутри InsureTech заменены publish/subscribe.
